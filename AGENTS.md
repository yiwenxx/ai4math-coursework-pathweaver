# Public development rules

- Read README.md and STATUS.md before making capability claims.
- Keep generic interfaces independent of domain implementations.
- Do not invent discoveries, benchmark results or progress.
- Keep candidate programs separate from trusted verification.
- Include only distributable source, examples and documentation.
- Default validation is compilation/build. Add focused tests when required by the change.
- Public inventory changes are maintained with the delivery workflow; do not silently disable the check.
